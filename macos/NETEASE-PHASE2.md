## 范围与行为

四档音质：128 kbps、320 kbps、无损、Hi-Res。默认128，旧配置保持兼容。
无损与Hi-Res请求FLAC。每级最多一次有限降级，网络、登录和取消不触发降级。
返回低档可播放音源时直接使用，显示实际返回等级与文件采样率、位深和声道。
Hi-Res不等于24/192保证；Unity混音和系统输出不提供bit-perfect保证。

FLAC先完整下载、校验压缩文件大小/摘要、完整解码校验PCM帧数及STREAMINFO MD5，
再由后台线程分块解码。8秒PCM缓冲、2秒预填、32 MiB工作缓冲预算；音频回调只复制/补零。
默认FLAC下载180秒总超时、15秒停滞超时、1 GiB硬上限。
磁盘缓存默认512 MiB，单文件缓存默认256 MiB，显式旧配置值不覆盖。
播放中的文件有租约；缓存登记失败继续使用临时文件；关闭后清理。

支持原生FLAC，单/双声道、16/24-bit、8–192 kHz、已知总帧数且不超过Unity的INT32帧数上限。
不增加外部播放器、DRM解码、SVIP母带或环绕音效。

## 构建与自动测试

在仓库根目录：

```sh

python3 -m unittest discover -s macos/tools -p 'test_*.py'
MUSICBRIDGE_BUILD_DEST="$PWD/macos/dist/NeteasePhase2" ./macos/build.sh
```

测试素材由开发机FLAC参考编码器生成，不要求最终用户安装编码器。

### 性能门槛及可选优化

固定STAY/迷星叫交替20次：10次缓存命中、10次真实下载；文件准备/预填P95 4.030秒，最大4.554秒；下载P95 3.059秒。另行20次只读取址P95 0.138秒、最大0.149秒。这是独立阶段采样，不能把P95简单相加当成配对端到端首声数据。

下一首预下载达到2秒门槛，已实现为1.4.1.0候选：`Netease.NextAudioPreload=false`默认关闭。只预取顺序队列或FM确定的下一首，不预测随机/单曲循环；每次最多保留一个压缩音频文件，不创建AudioSource或完整PCM。前台播放先重新取址确认授权/元数据，再一次性接管预取租约。FLAC预取完整性已验证时，前台重新检查文件摘要后复用验证结果。MP3在前台Unity解码成功后才登记缓存。暂停/让位/加载/缓冲、换号、换队列或音质变化时取消失效预取；后台失败不改变正常播放。

2026-09-23 ARM游戏内对照：顺序队列从《Morning Energy》进入《迷星叫》，日志确认3次FLAC预下载命中；重新取址后 `load_s` 分别为1.579 / 1.586 / 1.614秒，`download_s=0`。以3次中的最慢1.614秒对比此前20次基线文件准备/预填P95 4.030秒，等待减少约60%；预下载计时还包含重新取址，故该比较对收益保守，但并非同一时刻的配对A/B网络实验。用户确认手动切歌不卡顿、正常出声，自然播完后自动进入下一首并正常出声。自然结束日志为 `consumed=frames=8726331`、`drained=True`、`underruns=0`。此结果支持FLAC顺序预下载的游戏内验收，不推断所有曲目或网络的P95。

同轮暂停/恢复日志：16:19:32进入Paused，16:19:44恢复Playing，16:19:46重新完成下一首预下载。16:20:02正常退出后，FLAC释放计数为 `handles=0 workers=0 leases=0`，`cache/audio/v2/work` 没有残留 `.part` 文件。此轮并未单独测量暂停瞬间的网络取消耗时。

网络流式尚未实现：本轮固定曲目的数据未充分触发5秒进入门槛，保留完整下载后分块播放。配对的 `lookup_s` / `prefill_s` / `load_s` 指标已用于预下载对照。
